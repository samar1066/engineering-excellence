# {{project_name}} infrastructure

## What this is

This directory was generated by `eep init` from the aws-cdk pack. It is a CDK v2 TypeScript application that deploys the project's container image to AWS Fargate behind an application load balancer, in three stages: `dev`, `uat`, and `prod`. The stage table in `lib/environments.ts` is the only place a stage is declared, and `lib/service-stack.ts` is the single stack every stage instantiates.

## Setup

Run `make setup` to install the locked dependencies with `npm ci`.

## Synth

Run `make synth` to render every stage's CloudFormation template into `cdk.out`. It needs no AWS credentials and reaches no AWS account: the stacks bind their account and region at deploy time, so this is the command that proves the definition still evaluates.

## Test

Run `make test` to synthesize each stage in process and assert what the templates contain: the load balancer, the Fargate service at that stage's desired count, the deployment circuit breaker, and the health check path.

## Diff and deploy

The image tag is the artifact reference, and it arrives as context so the same built image promotes through the stages unchanged:

```
npx cdk diff {{project_name}}-uat --context imageTag=<sha>
npx cdk deploy {{project_name}}-uat --context imageTag=<sha>
```

Read the diff before every deploy. `STACK.md` in the aws-cdk pack carries the full promotion contract, the cost notes, and the rules for changing a stage.

## Verify

Run `make verify` to run the full Engineering Excellence Program verification gate. It runs an installed `eep` when there is one and otherwise falls back to `npx engineering-excellence verify`, so Node 22 is its only extra prerequisite.

# Code of Conduct

This project is built by people who mostly do not know each other, judging each
other's work in public. That only holds together when the argument stays about
the work. This document states what is expected here, what is not tolerated,
where it applies, and who to tell.

## Expected behavior

1. Argue from evidence. A technical position is carried by a benchmark, a
   failing test, a specification, or the output of a command you actually ran.
   Preference is a fine place to start and a poor place to finish.
2. Review the work, never the person. Comment on the code, the check, the
   choice, the prose. Assume the author was trying to do the right thing with
   the information they had at the time.
3. Give credit accurately. Name the people whose work you build on, in
   frontmatter and in prose. Do not claim someone else's contribution, and do
   not quietly drop their name while editing their file.
4. Be direct without contempt. Clear feedback, delivered plainly and early, is a
   kindness. Sarcasm aimed at a contributor is not feedback.
5. Disagree through the process. If you think a law or a toolchain choice is
   wrong, open an issue and make the case. Route around the argument, not around
   the gate.

## Unacceptable behavior

1. Harassment in any form, including unwelcome sexual attention, unwelcome
   personal attention, and continuing after being asked to stop.
2. Personal attacks, insults, or demeaning remarks about a person or a group,
   including anything aimed at identity, background, or level of experience.
3. Publishing private information about anyone without their explicit
   permission: a home address, an employer, a private message, or an identity
   they have not published themselves.
4. Sustained disruption: derailing threads, reopening settled decisions without
   new evidence, or organizing others to pile onto a review.

## Scope

This applies in every project space: issues, pull requests, discussions, commit
messages, code and documentation contributed here, and any venue where you are
representing the project.

## Enforcement

Report a violation to the maintainer. The preferred route is a private report
through GitHub on this repository. If that is not available to you, write to the
maintainer address recorded in the git history for recent commits. Reports go to
the maintainer and are kept confidential, including from the person reported.

Maintainers may edit or remove comments, commits, code, issues, and pull
requests that violate this document, and may block a contributor from the
project temporarily or permanently. The response is proportionate: an isolated
lapse usually gets a private word first, while repeated or severe behavior gets
removal without one. Maintainers are held to this document exactly as everyone
else is, and a report about a maintainer is a report you should still file.
